## 1. 目标与范围

恢复首页“总结今天最重要的科技新闻”“总结我工作文件夹中的文件”两个建议入口，核验 Web 从登录、工作区到聊天回复的实际使用路径。保持现有共享 renderer、RPC、SessionManager 和 pi-durable 子进程边界；MCP 与 Codemode 默认启用的行为保持不变。

本次新规格和内核切换产生的专用文档统一放入 `docs/pi-durable/`。本地 `main` 已有的通用架构文档继续作为用户文档入口。无需新增依赖，不使用真实模型凭据、付费配额或用户工作目录，不提交、不推送。

## 2. 已确认事实

### 2.1 两个建议发送错误消息

调用链：`NewChatSuggestions.onSelect` → `ChatDisplay.handleRunSuggestion` → `newChatSuggestionMessage` → `handleSubmit` → 现有聊天发送路径。

`newChatSuggestionMessage` 为内置建议读取 `chat.suggestions.${kind}Prompt`。当前 `en` 和 `zh-Hans` 均缺少 `newsPrompt`、`filesPrompt`；真实 i18next 返回缺失键本身。原测试使用 `key => key`，只能检查键名路由，无法发现资源缺失。

复现结果：

| 入口 | 预期发送 | 实际发送 |
|---|---|---|
| 科技新闻 | 自然语言新闻总结请求 | `chat.suggestions.newsPrompt` |
| 工作文件夹 | 自然语言文件总结请求 | `chat.suggestions.filesPrompt` |
| Skills 对照 | 可用技能介绍请求 | 正常本地化提示词 |

真实 Web 页面中点击两个入口，聊天记录均出现上述错误键。该资源缺失也存在于本地 `main`，当前证据不能将其归因为内核切换。

### 2.2 Web 的初步结果

隔离生产构建成功，真实 headless server 的 `/health`、`/login` 返回 200。浏览器经正常认证进入工作区，可新建会话并点击建议。Vite 开发模式也能加载登录后的共享 renderer；目前未复现整站无法加载或连接的错误。

这不等于完整聊天验收通过。尚须用只监听 loopback 的模型替身检查聊天回复、实际子进程和持久化路径；若发现失败，先补充本节的具体触发条件和根因，再修复对应边界，不猜测改动 Web 架构。

所有配置通过当前代码实际读取的 `CONFIG_DIR` 隔离。`config/paths.ts` 顶部说明仍称 `MKAGENT_CONFIG_DIR`，与实际读取项不一致；本次不据此更改配置契约。

## 3. 实施方案

1. 为两种支持的语言补齐 `newsPrompt`、`filesPrompt`。新闻请求明确查询当天新闻并附来源；文件请求使用当前工作目录，先检查目录内容，再读取相关文件。目录不可用或为空时说明实际状态。
2. 保留现有建议组件、发送函数和工作目录传递，避免为资源缺失重写已存在的流程。保留 Skills 和自定义建议的既有行为。
3. 在现有建议测试中加入真实 locale/i18next 检查：遍历所有已注册语言和内置建议，断言提示词存在、非空且不等于原始键。先证明新测试在未修复资源上失败，再补资源并验证通过。
4. Web 使用临时构建目录、临时配置和模型替身运行。以浏览器操作验证登录、新会话、两个建议的正确消息和回复；不把构建或内部函数调用当作实际应用验收。如果 Web 特定失败可复现，记录根因和最小必要修改后再实施。
5. 将 `kernel-durable-switch-spec.md`、`kernel-migration-review-fix-spec.md` 移至本目录，保持历史技术内容和相互引用，修正旧路径引用。在本目录添加索引，在中英文文档首页增加入口；旧 `docs/migration/` 产品迁移归档保持其原有职责。
6. 更新任务内来源清单记录，执行必要检查并补充本规格的验收记录。

## 7. Web 开发代理连接失败补充规格

### 确认事实

用户日志：`[vite] http proxy error: /api/config`，`connect ECONNREFUSED 127.0.0.1:9100`。

- 本机当前仅 `5175` 有 Vite 监听；`9100`、`3100` 均无后端监听。此错误说明代理目标无服务接受连接，发生在认证及 agent 调用之前。
- `webui:dev` 仅启动 Vite，不启动 headless server；Vite 代理默认端口为 `9100`。
- `server:dev:webui` 却写死 `MKAGENT_RPC_PORT=3100`，与 Vite 和 headless bootstrap 的默认 `9100` 不一致，还会覆盖调用方提供的端口。
- 原中英文开发指南只列出了命令，没有说明两个进程的启动顺序、地址及端口配对。首次隔离验收为前后端显式指定相同临时端口，因此未覆盖默认脚本的端口差异。

### 修改方案与验收

以下为首轮端口修复记录；最终启动方式以本节末尾的“单命令启动补充”为准。

1. 从 `server:dev:webui` 删除固定 `3100`，沿用 bootstrap 的默认 `9100` 和现有 `MKAGENT_RPC_PORT` 覆盖入口；Vite 保持同一契约。
2. 中英文开发指南明确：先运行 `server:dev:webui`，可直接访问 `http://localhost:9100`；需要 HMR 时另开终端运行 `webui:dev`，访问 `http://localhost:5175`。自定义端口须在两个终端一致设置。
3. 不改认证、安全策略、应用运行架构，不自动访问真实用户配置或停止已有 Vite。
4. 使用现有 Vite 配置解析和无副作用的 shell 命令替身核验：默认后端端口与代理均为 `9100`，自定义 `MKAGENT_RPC_PORT` 不被脚本覆盖；通过临时 Vite 和本地 HTTP fixture 实际验证 `/api/config` 代理。fixture 只验证代理，不替代前次已完成的真实应用验收。
5. 更新 `package.json` 来源记录，执行受影响检查和 diff 检查。验收后记录结果。

### 实施与验收结果

- 已删除 `server:dev:webui` 固定的 `MKAGENT_RPC_PORT=3100`。后端默认端口现在沿用 `9100`，调用方自定义端口可正常传递。中英文开发指南已加入启动顺序、访问地址和代理连接失败说明。
- 使用 shell 函数替身执行修改前后的原始命令：旧脚本在默认和自定义端口两个场景均不一致；修复后分别得到默认 `9100` 和自定义 `19321`，与真实 Vite 配置解析得到的 HTTP/WS 代理目标一致。
- 启动临时 Vite 和本地 HTTP fixture，经真实 `/api/config` 代理返回 HTTP 200 和预期 JSON。验证脚本 `/tmp/mkagent-web-proxy-check.KPJ0Mj/verify.mjs` 退出 0，临时服务均已关闭。
- 本轮未启动用户配置的后端，未停止或重启已有 `5175` Vite，未访问凭据或调用模型；用户需启动后端后再访问页面。前次真实 Web 应用验收仍保留其原有边界。
- `package.json` 来源记录已同步，`git diff --check` 通过；前次来源审计的参考仓库缺失阻塞仍存在。

### 单命令启动补充（用户反馈仍失败后）

再次核验本机：运行链为 `bun run webui:dev` → Vite，只有 `5175` 监听，没有 headless server 进程。仅统一端口不能解决只运行该命令的场景。前一版修改的验收只覆盖端口和代理，不覆盖单命令启动，本次补齐该边界。

方案：`webui:dev` 先构建必要的 WebUI 和 Pi 产物，然后用已安装的 `concurrently --kill-others` 启动真实后端和 Vite。两者继承相同的端口和配置环境；任一进程退出时停止整组。后端保留现有开发模式配置和认证。移除原先按端口 `kill -9` 的做法，Vite 使用 `--strictPort`，端口已占用时明确失败，不停止其他进程。中英文说明改为单命令启动。

验证：在临时源码副本中运行该启动脚本，使用全新 `CONFIG_DIR` 和测试认证，实际验证前端页面、后端 health、认证后的 `/api/config` 及 WebSocket 握手。覆盖后端退出或前端端口冲突时整组退出。保留当前用户 Vite，不启动用户真实配置，不调用模型。

验收结果：

- `5175` 已被原 Vite 占用时，实际命令报告 `Port 5175 is already in use`，退出 1；`concurrently` 向本次后端发送 SIGTERM，临时后端端口无监听。原 Vite 继续运行，没有按端口终止既有进程。
- 正常路径只将临时副本的 Vite 端口改为 `65175`，使用同一个 `bun run webui:dev` 脚本。WebUI 构建退出 0（17.23 秒），Pi 子进程构建退出 0，真实后端和 Vite 均启动；后端 `/health`、认证后的 `/api/config` 返回 200。
- 实际 Vite 页面和 `/login` 代理可用；未认证 `/api/config` 返回 401，认证后经代理返回 200，WebSocket `/ws` 代理收到真实 `handshake_ack`。浏览器进入初始化页面，点击 `Setup later` 后显示完整应用壳和 `New Session` 入口。
- 验证后向本次后端发送 SIGTERM；后端正常退出，`concurrently` 随后停止配套 Vite。命令因子进程被终止返回 1，属于本次主动退出场景。临时后端、Vite 和登录辅助端口均无监听，浏览器 TaskSpace 已关闭，原 `5175` Vite 保留。
- 验证脚本与脱敏日志保留在 `/tmp/mkagent-web-start-check.R02Zy7/`。此轮验证覆盖实际启动链，不调用模型，不替代 §6 中已说明边界的聊天验收。
- 中英文开发文档已改为单命令启动，`package.json` 来源 hash 已同步。用户须先用 `Ctrl+C` 结束旧的 `webui:dev`，再运行新命令；刷新旧 Vite 不会应用启动脚本变更。
