## 目标与约束

MkAgent 主要基于 durable coding agent 运行：Coding 层承接 Pi coding agent 的能力和插件契约，已有 pi-durable 内核负责调度、存储及恢复，MkAgent 产品功能位于外层。当前功能是保留基线，先核实实际实现，不重新实施已有且满足契约的内核接入或 Coding 功能。

按接入 SDK 的方式二次开发：先使用 pi-durable 及独立公开包的接口和扩展点，协议差异通过外部薄适配连接；只有这些方式仍不能满足既定契约时，才在本项目修改上游 SDK 源码，并记录具体缺口。优先减少升级时的人工核对和适配维护量，不能只按删行数判断收益，也不能因调用协议不同就放弃公开接口。允许按需使用 pi-agent-core，生产不能直接依赖完整 pi-coding-agent，也不能运行上游 Agent loop。

普通与 coding 模式保留工具、提示词、权限和资源发现策略。是否共用 AgentSession、内部任务类型及原生投影范围属于实现选择，不作为独立验收条件。源码数量和哈希追溯不能证明架构已经符合公开包优先的要求。

停止迭代的条件是：在保留既有功能和插件契约的前提下，维护成本已降到最低。逐项核对仍可消除的本地重复实现、内部修改和升级适配；只要还有可实施的降低方案，就继续处理。每项保留实现须有已核实的契约缺口，并说明公开包和薄适配为何不能替代。未核实或受阻的项保持开放，不能因完成一批改动、测试通过或本地提交而宣告达到目标。
